# Filing Rules

Nothing too strict, just try to keep things consistent and avoid huge errors (eg. double entry) that can cause error in reporting data (eg. summary data).

Below some soft guidlines:

- [Categories](./categories.md) - picking between categories that overlap
- [Decisions](./decisions.md) - calls already made from transaction cases I wasn't sure about

At the end of the day important thing is to pickup trends and overall net spending, focus on accuracy of payment amount, reimbursement amount, categories. Minor things like what date to use or what merchant name to use is not too important.
